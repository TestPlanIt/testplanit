  <behavior>
    The service receives up to MAX_PAIRS_PER_SCAN (50) pairs and processes them in BATCH_SIZE (10) batches.

    Input:
    ```typescript
    interface PairWithCaseContent extends SimilarCasePair {
      caseAName: string;
      caseASteps: string;  // formatted "Step 1: ... Expected: ..." multi-line
      caseBName: string;
      caseBSteps: string;
    }
    ```

    Output: same pairs array, with:
    - Confirmed pairs: confidence upgraded to "HIGH", detectionMethod: "semantic"
    - Rejected pairs: removed from results
    - Failed batch pairs: kept with original fuzzy score, detectionMethod: "fuzzy"
    - When no LLM: all pairs returned unchanged, detectionMethod: "fuzzy"

    LLM prompt approach:
    - System: "You are a duplicate test case detector. For each pair, respond with YES if both cases test the same functionality, NO if they test different things. Respond ONLY with valid JSON: { \"results\": [{\"pairIndex\": 0, \"verdict\": \"YES\"}, ...] }"
    - User: numbered pairs, each with Case A name/steps and Case B name/steps
    - Parse response JSON; if parse fails, skip batch and keep originals

    Behavior tests:
    - Test 1: Empty pairs array → returns []
    - Test 2: No LLM configured (resolveIntegration returns null) → returns all input pairs unchanged with detectionMethod "fuzzy"
    - Test 3: LLM returns YES for pair 0, NO for pair 1 → pair 0 has confidence "HIGH" + detectionMethod "semantic", pair 1 removed
    - Test 4: Pairs capped at MAX_PAIRS_PER_SCAN (50) — 60 pairs input → only first 50 analyzed, remaining 10 returned with detectionMethod "fuzzy" unchanged
    - Test 5: Batch size — 25 pairs → 3 LLM calls (10, 10, 5)
    - Test 6: LLM call throws error for one batch → that batch's pairs kept unchanged, other batches proceed
    - Test 7: LLM returns unparseable JSON → batch pairs kept unchanged
  </behavior>
  <implementation>
    Create `testplanit/lib/llm/services/duplicate-detection/` directory.

    DuplicateAnalysisService constructor:
    ```typescript
    constructor(
      private llmManager: LlmManager,
      private promptResolver: PromptResolver,
    ) {}
    ```

    Key constants:
    ```typescript
    export const BATCH_SIZE = 10;
    export const MAX_PAIRS_PER_SCAN = 50;
    ```

    analyzePairs signature:
    ```typescript
    async analyzePairs(
      pairs: PairWithCaseContent[],
      projectId: number,
      userId: string,
    ): Promise<(SimilarCasePair & { detectionMethod: string })[]>
    ```

    Steps:
    1. If pairs.length === 0, return [].
    2. Call `this.llmManager.resolveIntegration(LLM_FEATURES.DUPLICATE_DETECTION, projectId)`. If null, return pairs mapped with `detectionMethod: "fuzzy"` (strip caseAName/caseASteps/caseBName/caseBSteps from output).
    3. Slice pairs to MAX_PAIRS_PER_SCAN. Pairs beyond the cap are returned unchanged with `detectionMethod: "fuzzy"`.
    4. Build LLM batches of BATCH_SIZE from the capped slice.
    5. For each batch:
       a. Build system + user prompt describing the pairs.
       b. Call `llmManager.chat(integrationId, { messages, temperature: 0.1, maxTokens: 512, userId, projectId, feature: LLM_FEATURES.DUPLICATE_DETECTION })`.
       c. Parse response JSON to get `{ results: [{pairIndex: number, verdict: "YES"|"NO"}] }`.
       d. On parse error or LLM error: skip batch, keep all batch pairs with `detectionMethod: "fuzzy"`.
       e. Pairs with verdict YES → detectionMethod: "semantic", confidence: "HIGH".
       f. Pairs with verdict NO → excluded from output.
       g. Pairs missing from response → kept with `detectionMethod: "fuzzy"` (conservative).
    6. Concat: processed results + uncapped overflow pairs.
    7. Return, stripping caseAName/caseASteps/caseBName/caseBSteps (return SimilarCasePair shape only).

    For tests, use vi.mock for LlmManager and PromptResolver. Use vi.hoisted() pattern per Phase 49 decision for mock objects.
  </implementation>
</feature>
