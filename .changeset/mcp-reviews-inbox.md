Add Review inbox tools. `testplanit_reviews_list` returns the review requests assigned to the authenticated user — the same queue as the app's Review inbox: `view: "pending"` (default) returns PENDING requests awaiting the caller's decision oldest-first, `view: "decided"` returns the caller's own decision history newest-first. Both assignment branches are covered — direct assignment and assignment to a role the caller holds — and there is deliberately no user filter, so the tool can only ever return the caller's own work. Rows resolve the polymorphic subject to `entityName` (with `entityDeleted`, since a request can outlive its subject), and carry the requested workflow `transition`, the requester, `assignedTo` with its `via: "USER" | "ROLE"` discriminator, the requester's submit-time note as plain text, and — on the decided view — the decision, its comment, and who made it. Requests from projects with the review workflow turned off are excluded, and `reviewFeatureEnabled: false` distinguishes "the feature is off system-wide" from "nothing is assigned to you". Filters: `projectId`, `entityType`; cursor pagination throughout.

`testplanit_reviews_decide` records an APPROVED / CHANGES_REQUESTED / REJECTED decision on behalf of the token owner. It calls the same host route the app does, so every rule still applies: eligibility (assignee — directly or through an assigned role — with approve permission for the entity's area, or system admin), the append-only PENDING-guarded flip, the paired decision comment addressed to the requester, the requester's notification, the webhook, the audit event, and the fact that **approving applies the requested workflow transition** to the entity. A comment is required for CHANGES_REQUESTED and REJECTED. Read-only (`mode:read`) tokens are refused before the decision runs, and the tool description tells agents to confirm with their user before deciding.

`testplanit_reviews_decide` requires a TestPlanIt instance whose `POST /api/reviews/{id}/decide` accepts an API token — that server change ships with this release. Against an older instance the tool reports exactly that rather than blaming the token, and `testplanit_reviews_list` is unaffected because it needs no new server surface.
